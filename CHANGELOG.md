# Changelog

## [Unreleased]
- **feat(map-ui):** open the location picker as a full-screen map dialog
  - Choose location now opens a native modal with a large map, a Google-Maps-style search dropdown and single-line saved/default bookmark rows instead of expanding the lobby card.
  - Selecting a result, marker or bookmark applies the same flight plan and closes the dialog; the native dialog keeps focus handling and Escape-to-close. Covered by `npm run test:map-scroll` and 390×844/1440×900 Chrome screenshots.
- **fix(map-ui):** let the lobby panel scroll from the map on touch screens
  - A one-finger vertical drag on the map now scrolls the surrounding lobby panel instead of being swallowed by the map's `touch-action: none`; one-finger horizontal drags still pan the map, and two-finger gestures still pan and zoom it.
  - Covered by `npm run test:map-scroll` in 390×844 hardware Chrome.
  - The browser check rejects SwiftShader before launching Chrome, so software rendering cannot be used as evidence.
- **fix(map-ui):** make the lobby map usable with touch on phones
  - Airport and cruise pins keep the same on-screen size at every zoom and carry a 44 px invisible tap circle, so they can be selected from the world overview instead of shrinking to a few pixels.
  - Mobile zoom, search and bookmark controls now use 44 px touch targets; the missing search glyph is drawn in CSS. Covered by `tests/mapBrowser.test.js` and a 390×844 Chrome check.
- **feat(aircraft):** export the Cessna 172 pilot as a GLB
  - `npm run build:pilot` now writes `public/models/pilot-c172.glb` with the seated yoke/pedal IK pose baked into its named limb nodes.
  - The C172 swaps to the GLB at runtime with the procedural pilot as fallback; the model joins the 3D asset gallery and is covered by `tests/civilPilotGeometry.test.js`.
- **feat(demo):** add the F-16 Incheon → Gimpo sortie demo
  - Selecting the F-16 at Incheon now offers a second cinematic demo: runway takeoff, a heading-led transit to the streamed RKSS airport, RW14R interception, a 3° final and a braked rollout with manual handover on the runway.
  - The demo owns its destination: it mounts and reads the streamed Gimpo runway before releasing the takeoff, so no lobby destination choice is required. Stage captions are available in English and Korean.
  - Registered in the demo sweep route table and covered by `tests/f16GimpoDemo.test.js`; the hardware-GPU sweep verifies staged flight, landing and parked handoff.
- **feat(record):** record an F-16 Incheon → Gimpo sortie as an mp4
  - `scripts/record-flight-video.mjs --destination rkss` targets the streamed RKSS runway using its indexed threshold and course, with a hardware Vulkan Chrome screencast encoded by ffmpeg. `--destination jeju` keeps the existing Incheon → Jeju flight and output name.
  - The flight-persona anomaly evaluator now samples the recorded sortie; anomalies and a flight summary are saved with the controller log in `<output>.frames/flight-report.json`.
  - Covered by `tests/recordFlightVideo.test.js` and the hardware-GPU `--controller-check --destination rkss` phase gates.
- **feat(camera):** add opt-in webcam head look for mobile and desktop
  - A new head-tracking panel requests the front camera on click, detects a face with locally hosted MediaPipe assets, and drives a dedicated yaw/pitch channel in cockpit, wing and gear views.
  - Explicit mouse/touch look keeps precedence over head look, and the tracking assets load only when the feature is enabled. Reset zeroes at the current head position; Calibrate uses recent head movement as the full look range.
  - MediaPipe assets are served from `public/mediapipe` with the Apache-2.0 licence in `public/licenses/mediapipe-LICENSE.txt`.
- **feat(landmarks):** automatically discover, rank, and display major landmarks from Overture Maps
  - `GeographicLandmarks` and `src/geospatial/overtureLandmarks.js` automatically extract cities, districts, airports, bridges, towers, peaks, national parks, large campuses, and tall non-residential buildings from streamed Overture Maps PMTiles (`divisions` z9–z10, `base` z11/z13 with camera look-ahead, and shared `GeographicGreenSpace` / `GeographicBuildings` tiles) without requiring manual per-place configuration.
  - `nearestLandmarks()` now ranks candidates by prominence-weighted priority (`landmarkPriorityScore`) and resolves dynamic terrain-relative heights (`resolveLandmarkHeight`), while `dedupeLandmarks()` collapses duplicate names/Wikidata IDs and `LandmarkPins` adds `city`, `bridge`, `park`, and `water` pin icons.
  - See [landmark pins](docs/development/landmarks.md); covered by `tests/overtureLandmarks.test.js`, `tests/geographicLandmarks.test.js`, `tests/landmarks.test.js`, and `tests/landmarkPins.test.js`.
- **feat(landmarks):** add data-driven named-place pins with importance and category icons
  - Any WGS84 place with localized names, an optional elevation, category tags and a 1–5 importance level can be added to `src/config/landmarkPlaces.json`; pins no longer need per-place code.
  - Candidates are projected into the active map's local frame, filtered by importance-scaled range/category and shown nearest-first with overlap suppression; custom datasets and category filters can be passed to `LandmarkPins`.
  - Pins are circular markers with a pointed tip and a kind-specific icon, falling back to a generic pin icon for unknown kinds.
  - See [landmark pins](docs/development/landmarks.md); covered by `tests/landmarks.test.js` and `tests/landmarkPins.test.js`.
- **feat(assets):** add decimated LOD variants for 1 MiB+ GLBs to the 3D asset gallery
  - `npm run build:lod` simplifies every `public/models` GLB of at least 1 MiB to 10% of its triangles with meshoptimizer and writes the result to `public/models/lod/`, preserving Draco compression, node names and materials.
  - Variants that cut the payload by less than 15% are dropped, so the texture-bound Cessna 172 gets no near-duplicate; the two 737 cockpits (39% / 52% smaller) and the F-16 (24% smaller) gain gallery entries marked `LOD`.
  - Runtime aircraft and cockpit loaders still use the full assets; see [asset LODs](docs/development/asset-lod.md).
- **fix(effects):** avoid scene-wide shader recompiles on the first explosion
  - Explosion flash lights now stay visible at zero intensity instead of being hidden. Three counts visible point lights in every lit material's program key, so the old visibility toggle rebuilt the whole scene on impact.
  - The explosion's flipbook, spark and shockwave programs are linked behind the existing startup shader gate, and one reusable flash light replaces the four-light pool.
  - On Intel/Vulkan, a cold bandit detonation dropped from 1097–2440 ms to 195 ms with no new shader programs; steady-state frame time stayed within the run-to-run range with the idle light present.
- **feat(ui):** draw the aircraft-control and fullscreen buttons as icons (#808)
  - Landing gear (with its down/up/moving/failed arrow), spoilers (a wing section with its upper panel raised, matching the flap icon; the highlighted button shows when they are out) and fullscreen (enter/exit) now show icons instead of short text.
  - Flaps show a wing-and-flap icon above their angle; on desktop the key hint sits beside the angle.
  - Reverse thrust reads `REV` in Korean too, as cockpit engine displays print it. Take control and the camera views keep their text labels.
  - Icons follow the button colour, so disabled controls and the idle portrait row dim exactly as the text labels did; screen readers still hear the full label.
- **fix(replay):** stop the aircraft after playback ends
  - A parked replay (end of track, manual pause, or a terrain wait) now silences the continuous engine/wind/pack bed, clears cockpit vibration and stall buffet, and freezes propeller/fan/strobe animation instead of droning and shaking over the final frame.
  - Crash impacts and other one-shots stay audible, because a replay can stage its final impact on the same frame that parks playback; resuming, scrubbing away from the end sample, or restarting restores the recorded mix and motion.
  - Leaving the replay releases the held state.
- **feat(replay):** identify the jet and live missiles in DIRECTOR replays
  - The DIRECTOR camera now labels the replay host aircraft and each live recorded round, so a cut to a missile-follow or bandit shot still says which object is the player.
  - Off-screen subjects get an edge arrow with range; markers follow the interpolated replay poses, survive pause and seek, and appear only during replay.
- **fix(ui):** keep the cockpit eyepoint panel out of the forward sight
  - The panel now docks to the bottom edge over the lower console instead of opening under the toolbar across the windshield and HUD; its height is capped below the measured control rows and it scrolls internally when needed.
  - Viewports shorter than 560px get a thin three-column strip (axis labels above their values, no optional step buttons) and the cockpit POV pill becomes a 44px eye icon, so the horizon and HUD stay visible on landscape phones.
  - Verified at 1440×900, 926×428, 390×660, 390×844, 320×568, 568×320 and 320×400: the pill clears the toolbar and the panel stays below the upper 35% sight band, bottom-docked.
- **feat(render):** make quality tiers differ in real geometry (#815)
  - `performance` now caps the framebuffer at 1280 × 720 and uses 128 terrain / 96 water segments; `balanced` uses 192 / 144 instead of sharing the high tier's 256 / 180.
  - Quality changes rebuild the terrain and sea grids and let the foliage layer rebuild its roads against the new grid; the sea keeps its fixed 200 m camera snap step.
  - On a 1440 × 900 desktop, `performance` therefore renders about 28% fewer pixels and 40% fewer world triangles than before; the cockpit geometry and its shadow cost are unchanged.
- **fix(combat):** audible missile launch and countermeasure ejection, and downed bandits that stay visible
  - Missile ignition now plays a highpass report over a broad rocket roar and low thump, loud enough to read over the engine/wind bed; replay launches are scored after the DIRECTOR camera has cut to the launch shot instead of against the previous orbit camera kilometres away.
  - Bandit flare and chaff ejection have their own distance-scaled synthesized voices (flare crack plus burn hiss, chaff pneumatic puff) in live sorties and replays; these stems did not exist before.
  - A killed bandit no longer blinks out: its airframe keeps the last measured flight velocity, tumbles and burns until terrain impact (or 20 s), then hides until the 8 s respawn. Presentation only; target state, damage, kill and respawn contracts are unchanged.
- **feat(weapons):** give each bandit a distinct aggressor livery
  - Patrol `BANDIT 1` and `BANDIT 2` now fly desert-sand and blue-gray airframes with slot numbers on the nose; the canyon chase aircraft uses the lizard scheme and an orange flash.
  - Wingtips and fin tips carry the callsign accent, and the loaded F-16 airframe, moving control surfaces and empty rails are repainted instead of matching the player's gray aircraft.
  - Livery selection is deterministic from the callsign, so respawns and recorded replays keep the same colors.
- **fix(diagnostics):** report the seeker's own estimate in IR tracking traces
  - The combat-situation trace now records the estimate-referenced line of sight and estimate range (`seekerLosAngleDeg`, `seekerEstimateRangeM`), so a decoy-induced gimbal trigger is visible; the existing bandit-referenced angle could not show it.
  - A memory-state seeker now reports the incumbent's loss reason when a competitor is visible, instead of the competitor's observation; the guidance estimate itself is unchanged.
  - No missile coefficient, flare parameter or gameplay behaviour changed; the 2.5 km audit produces identical terminals before and after. See [IR observation model review](docs/development/ir-observation-model-review.md).
- **fix(weapons):** point missile and bandit noses forward
  - AIM-9X/AIM-120C and air-combat bandit nose cones were rotated so their apex trailed the fuselage; they now lead along the local -Z forward axis.
  - The canyon-chase bandit's cone fuselage uses the same corrected orientation.
- **fix(replay):** make recorded bandit kills visible and audible
  - Combat replays open in the DIRECTOR camera, so the launch → missile-follow → bandit shot plays without hunting for a view.
  - The bandit shot now frames the target airframe from behind and beside it with the inbound round, replacing the canopy-side eye that showed only the missile.
  - Detonations and the replay's own crash play a distance-scaled burst from the replay camera; seeking back still suppresses past bursts.
  - Air bursts blend fire normally and use a darker smoke core so the explosion reads against bright sky and cloud.
- **feat(camera):** director camera missile cinematics
  - A rail release in `DIRECTOR` mode cuts immediately to a wing-mounted launch shot, then a rigid follow cam on the missile, then an over-the-shoulder bandit shot as it closes.
  - The bandit shot waits for a 1.6 km entry range, frames the target airframe and the inbound round, and holds through detonation.
  - Recorded sessions feed the same sequence from the replay combat track; shot pacing follows replay speed and pause, and seeking mid-flight skips the launch beat.
  - `CameraSystem.setCombatStateProvider()` selects recorded combat during replay playback and the live missile/bandit arrays otherwise.
- **fix(replay):** show F-16 missile launches, bandit targets and bursts in recorded replays
  - Replay tracks now carry a compact combat section (codec v4) with 2 Hz bandit poses, 20 Hz missile poses, detonation/expiry markers and the rail loadout mask.
  - Playback interpolates the recorded combat state, stages each detonation once, and restores the fired-rail count and time-correct splash count; it never re-simulates guidance, so seeks and speed changes cannot alter the outcome.
  - Replay HUD, cockpit and chase overlays show recorded bandits as target designators.
  - B737/C172 and older v1–v3 tracks remain readable; combat samples are thinned before pose samples when the entry budget is tight.
- **feat(combat):** F-16 AIM-9X/AIM-120C rail missiles, TPN guidance, HUD lock and RWR (#612 Sprint 1)
  - Six procedural rail missiles (4× AIM-9X, 2× AIM-120C) mounted on the F-16 wingtip and underwing stations; fired stations hide their mesh and reload on preset restart.
  - 120 Hz continuous rocket mass/thrust, atmospheric drag, gravity, 3D true proportional navigation, seeker gimbal limit and closest-approach proximity fuse.
  - Two patrolling bandit drones, HUD target designator / lock diamond / `SHOOT` cue / off-screen locator, weapon and splash inventory, and a 360° RWR display.
  - Three-stage RWR audio (search ping, lock beep, launch siren), missile launch whoosh and lock tone.
  - `Enter` fires, `N` cycles targets, with matching touch buttons; see [air-to-air missiles](docs/development/air-to-air-missiles.md).
- **feat(ui):** make gradual gaze reset optional (#658)
  - Added a persisted Auto gaze reset option so a released drag or hat-switch glance can hold its off-center view instead of slowly returning to the default.
- **fix(audio):** boost mobile & Bluetooth headphone loudness, makeup gain, and route recovery
  - Added post-compressor makeup gain (+4.1 dB, 1.6x) and normalized pink noise buffer to reach commercial game loudness standards (~ -14 LUFS RMS).
  - Added 4-stage volume cycling: 100% (Normal) → 150% (Mobile Boost) → 200% (Bluetooth Max Boost) → Muted → 100%.
  - Added continuous cockpit avionics cooling fan and ECS pack ventilation hum (`packSynth`) to eliminate dead silence on runway/idle.
  - Implemented persistent keep-alive gesture listeners and Web Audio `interrupted`/`suspended` auto-resume to handle Bluetooth earphone route switches on iOS/Android.
  - Retuned turbofan engine acoustic filter from 180 Hz to 280–1200 Hz sweet spot for mobile transducers and wireless earbuds.
  - Added dual-spool CFM56 N1/N2 turbine whine harmonics and ground rolling runway rumble.
  - Added on-screen sound & volume toggle button to preset bar, action panel, and mobile touch overlay.
- **feat:** camera‑anchored infinite ocean mesh and touchdown smoke realism (merged #29)
  - Ocean mesh now anchored to camera with grid snapping (`snapStep`).
  - Realistic tire smoke on landing gear; brake‑intensity threshold and nose‑wheel exclusion.
  - Updated Boeing 737‑800 landing‑gear geometry to official specs (wheeltrack 5.72 m, wheelbase 15.60 m).
  - Added verification script `scripts/verify-ocean-views.js` and unit test `tests/waterOcean.test.js`.
