# 인천 4단계: 수동 비행과 공항 접지

Discussion [#216](https://github.com/stlim0727/flight3d/discussions/216)의 4단계입니다.
메인 로비의 **인천공항 (RKSI)**에서 15R 이륙 준비, 1.5km 최종 접근, 750m 순항을
선택합니다. B737과 C172를 지원합니다. 인천 자동 데모는 제공하지 않으며 로비 배경은
정지합니다. P키로 기존 해안 공항 데모를 잘못 시작하는 것도 차단합니다.
독립 `/incheon.html`의 1~3단계 비교 기능은 유지합니다.

시화방조제·조력발전소·달전망대·방아머리해변의 추가 범위와 자료는
[시화 지역 확장](incheon-sihwa.md)을 참고하세요.

## 좌표와 실제 시설 범위

기존 원점(37.448°N, 126.455°E), +X 동 / +Z 남, m 단위를 그대로 사용합니다.
2km 상세 패치에는 활주로 일부만 있지만, 보관된 OSM 원본에는 해당 way의 전체 node가
있습니다. 같은 원본의 완전한 도형만 별도로 추출해 **활주로 2개, 유도로 way 165개,
에이프런 3개**를 제공합니다. 인천공항 전체의 모든 활주로나 시설을 복원한 것은 아닙니다.

```sh
node scripts/scenery/build-incheon-airfield.mjs
```

원본 SHA-256과 바이트 수를 검사하고 `src/config/incheonAirfield.json`을 재생성합니다.
이 JSON은 기존 원본과 동일한 **ODbL 데이터**입니다. 런타임에 외부 지도를 요청하지 않습니다.
전체 길이 약 3.75km인 15R/33L과 15L/33R의 방향·폭은 OSM 좌표와 태그에서 가져옵니다.
15R 진방위는 약 **144.682°**입니다. 표시 번호 15R은 진방위 반올림값으로 바꾸지 않습니다.
OSM 끝점을 모형 문턱으로 사용하며 별도의 displaced threshold/공시 운용 거리는 반영하지 않습니다.

15R 시작점은 (-1645.93, -3747.17), 반대 끝점은 (515.36, -696.68)입니다.
이륙은 시작점에서 100m 안쪽, 접근은 1.5km 바깥의 3° 경로에서 시작합니다.
기체별 속도와 CG-바퀴 높이를 적용하고 기존 trim solver가 공중 시작의 평형을 계산합니다.
APP 편차, ND 활주로·접근선과 CDU의 RW15R 표시도 같은 접근 좌표를 사용합니다.
공시 계기접근 절차, VOR/ILS 주파수 재현은 아닙니다.

## 렌더링·접지·충돌의 공통 표면

Copernicus DSM과 기존 해안선을 재사용합니다. 공항 포장은 앞 단계의 7m 기준을 확대
적용한 **모형 근사**이며 실제 종단·횡단 측량값이 아닙니다. 유도로도 이 높이를 사용합니다.
포장 주변 40m까지 같은 높이를 유지하고 추가 80m에서 원래 지형으로 부드럽게 복귀합니다.
원본 DSM 및 이전 단계 산출물은 수정하지 않습니다.

비행용 25m 격자를 한 번 생성하고, Three.js PlaneGeometry의 실제 삼각형 평면과 같은
보간으로 `getHeight`를 계산합니다. 지역 메시, 중심 상세 메시, 바퀴, 동체, 카메라가 이
sampler를 공유합니다. 중심 12.5m 메시의 세분화도 같은 평면을 유지합니다. 포장면과
차선은 Z-fighting 방지용 1.5~4cm만 띄웁니다. 수면은 0m이며 조석은 없습니다.

기존 지면 텍스처·외벽 배치·나무 인스턴싱을 재사용합니다. 공항 포장과 선은 색상별로
병합하며 개별 광원이나 차량을 추가하지 않습니다. 포장 외곽은 실제 폴리라인 폭/다각형으로
판정하고 공항 도로를 일반 자동차 도로와 구분합니다. 건물 충돌은 렌더링에 사용한 실제
윤곽과 높이를 사용하며, 오목한 터미널의 빈 부분을 AABB 전체로 채우지 않습니다.

추적·조종석·기어·드론·관찰 카메라가 활성 지형을 따릅니다. 고정 관찰 카메라 위치는
모형 관측점이며 실제 인천 관제탑의 측량 위치나 높이가 아닙니다.

## 로딩과 전환

인천 선택 시 자산을 한 번 비동기로 읽고 준비가 끝나면 환경을 전환합니다.
그동안 Fly는 비활성화됩니다. 실패하면 기존 공항을 유지하고 선택을 다시 눌러 재시도할 수
있습니다. 로딩 중 다른 공항을 선택하면 늦은 완료가 선택을 덮어쓰지 않습니다.
인천을 재방문할 때 메시와 텍스처를 다시 만들지 않습니다.
공항 전환 시 충돌·카메라·이펙트·항법 표시를 함께 연결하고 리셋은 기존 비행 상태 초기화를 사용합니다.

## 검증

```sh
npm run check
npm test
VITE_BASE_PATH=/flight3d/ npm run build
npm run preview -- --host 127.0.0.1 --port 5196 --base /flight3d/
APP_URL=http://127.0.0.1:5196/flight3d/ chrome-session --project flight3d node scripts/verify-incheon-flight.mjs
```

로컬 check·전체 **585개 테스트**·`/flight3d/` 프로덕션 빌드를 통과했습니다.
Intel ADL-N / ANGLE Vulkan에서 B737과 C172가 각각 이륙, 접근·착륙과 5초 정지를
완료했으며 충돌·착륙 사고·기어 손상이 없었습니다. 유도로 지상 이동, 로딩 실패/재시도/취소,
건물 충돌 후 리셋, 공항 전환, 카메라 모드와 390px 레이아웃도 검사했습니다.

Node 검사는 원본 전체 활주로 좌표·길이·높이, 포장 마스크, 기체별 시작과 접근 편차,
렌더 삼각형/접지 높이 일치, 수동 공항의 로비 정지 및 데모 차단을 다룹니다.
브라우저 검증 스크립트는 기존 PilotControlLaws를 **검증용 조종 입력**으로 사용합니다.
이것은 인천 자동 데모를 제품에 추가한 것이 아닙니다. 시작 이후 물리 위치를 덮어쓰지
않고 이륙 및 접근 → 플레어 → 접지 → 감속 → 5초 정지를 실행합니다.
건물 충돌 검사는 충돌 지점에 배치하는 별도의 재현이며 이후 초기화와 10초 접지를 검사합니다.
촬영 시 물리는 일시정지하고 일시정지 메뉴만 숨깁니다.

## 남은 한계와 다음 단계

실제 지형은 12 × 12km, 도시 상세는 중심 2 × 2km입니다. 영역 밖은 높이 0의 연속
수면으로 처리하며 실제 확장 지형이 아닙니다. DSM의 건물·수목 잔류와 낮은 해상도,
추정 건물 높이, 일반화한 외벽·주차선, 평면화한 고가/지하 도로는 남아 있습니다.
활주로 표시는 일반화한 점선·활주로 번호와 끝단 바이며 실제 등화·표지·유도로 표지판 전체를 재현하지 않습니다.

4단계 당시의 후속 목록이며, 근거리 차량과 전체 비행 비교는 [5단계](incheon-traffic.md)에서 다룹니다.
도시 범위 확장, 공항 전 시설, 정밀 지상 이동 경로 안내, 인천 자동 데모는
별도 후속입니다. **전체 비행 FPS/p95·메모리·로딩 끊김 비교는 5단계**에서 수행합니다.
결정적 물리 가속 검증을 실제 시간 FPS 측정으로 해석하지 않습니다.
