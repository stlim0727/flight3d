## 문제와 목표

국제공항 시나리오의 가상 도시는 산·들판 위에 빌딩이 흩어져 있어 도시로서의 연결성이 부족합니다. 도로, 공원, 주차장, 차량을 더해 공항 접근 비행에서 설득력 있는 풍경을 만드는 아이디어를 모읍니다. 아직 구현 결정을 내리는 단계는 아닙니다.

현재 `src/environment/FoliageAndCities.js`는 세 개의 원형 군집에 건물을 무작위로 배치하고 지면 높이를 사용합니다. 바다와 활주로 영역은 제외하지만 경사·도로 접면·블록·용도에 따른 배치는 없습니다. 건물 모델보다 배치 구조와 지면 표현을 먼저 개선하는 편이 효과적이라는 가설입니다.

## 시안 A — 가상 도시의 구조 개선

1. 급경사 건축을 제한하고, 완만한 지역에 도시 구역과 부지를 설정합니다. 평탄화가 필요하면 지형·건물·충돌 높이를 일치시킵니다.
2. 공항 진입도로 → 간선도로 → 블록 순서로 구성하고 건물을 도로에 맞춰 배치합니다.
3. 공항 주변은 물류창고·호텔·주차장, 외곽은 저층 주거, 도심은 중고층으로 밀도를 나눕니다.
4. 아스팔트·보도·주차면·공원·가로수로 건물 사이 초원을 대체합니다. 산지는 숲과 자연 지형으로 남깁니다.
5. 차량은 먼저 정해진 차선을 따라 이동하는 시각 효과로 시작합니다. 교차로 제어와 정교한 교통 모델은 후속 선택입니다.

항공 시점에서는 차량 수보다 도로망·블록·지면 패턴을 우선합니다. 차량과 가로수는 근거리 위주로 표시하고, 반복 건물은 인스턴싱과 거리별 상세도로 비용을 제한합니다.

## 시안 B — 실제 배치 데이터 + 절차 생성 외관

실제 도로망·건물 윤곽·높이·녹지 구역을 가져오고, 건물 외관과 차량은 기존 Three.js 장면에 맞춰 생성합니다. 실제 배치의 설득력을 얻으면서 낮밤 표현과 성능을 제어하는 혼합 방식입니다. 실제 도로를 현재의 무관한 가상 지형 위에 단순히 얹지 않고, 지형·해안선·좌표계·높이 기준도 함께 맞춰야 합니다.

## 사진 기반 도시 스트리밍이라는 다른 선택지

[Google Photorealistic 3D Tiles](https://developers.google.com/maps/documentation/tile/3d-tiles)는 사진 기반 풍경을 가져오는 경로입니다. API 비용·이용 조건·출처 표시·타일 스트리밍을 검토해야 합니다. 사진 메시만으로 움직이는 차량, 개별 건물 충돌, 낮밤 조명이 자동 해결되지는 않습니다. 다운로드 가능한 도시 메시도 용량 축소와 거리별 상세도 작업이 필요합니다.

## 작은 범위에서 비교할 제안

공항 옆 약 2 × 2 km를 대상으로 A와 B를 비교하면 좋겠습니다. 같은 카메라·고도·시간대에서 접근 비행 시점과 근접 시점을 확인하고, 도로 연결성·건물의 지면 정착·접근 경로 여유·로딩 용량·프레임 시간·메모리를 비교합니다. 수치 목표는 대상 기기와 시안 측정 후 정합니다.

논의할 질문:

- 현재 가상 공항의 분위기를 유지할지, 실제 공항 재현을 새 시나리오로 만들지?
- 첫 실험은 가상 도시 블록 개선과 스키폴 주변 실제 배치 중 어느 쪽이 좋은지?
- 주로 보는 고도에서 도시의 구조와 지상 디테일 중 어디까지 필요한지?
