# 창밖을 보고 내 위치 찾기

## 현재 시안 · 동남권 약도

#932의 지도 스타일 피드백에 따라 부산 C172 자유비행에서는 경상남도·부산·울산의 고정 권역도를 펼친다. 실제 행정 경계와 해안, 강, 주요 도로를 간략하게 그리며 현재 권역 전체에 옅은 색을 입힌다. 지도 중심과 축척은 고정하고, 붉은 기체 표식이 실제 위치와 기수 방향을 따라 움직인다. 연안에서는 인접 권역을 표시하고 범위를 벗어나면 ‘표시 권역 밖’으로 안내한다. 아래 상세 위치·확인 지점 기획은 이전 시안의 기록이다. [이슈 #932](https://github.com/stlim0727/flight3d/issues/932) · [Natural Earth 1:10m 데이터](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/)

[#1018](https://github.com/stlim0727/flight3d/issues/1018)부터는 모든 실제 지역(인천·제주·루클라·지도에서 고른 임의 지점)에서 기종과 관계없이 지도를 펼친다. 펼친 위치가 위 권역도 범위 안이면 권역도를, 밖이면 기체를 중심으로 한 북쪽 위 기본 지도를 쓴다. 기본 지도는 지형과 같은 Overture z11 수역 타일로 해안선을, OurAirports 인덱스와 공항 보정값으로 활주로를 그리며 약 40×28 km 이상을 보여 준다. 기체는 장면이 그려지는 원점 평면(사용자 원점, 없으면 기준 공항 원점)으로 역변환하고, 스트리밍 공항은 장면과 같은 인천 평면 배치를 거쳐 그린다. 그래서 루클라처럼 인천 평면이 약 21° 회전한 곳에서도 창밖과 방향이 맞는다. Coastal·네온 메트로폴리스·생성 계곡에서는 지도 메뉴를 숨기고 요청을 시작하지 않는다. [기본 지도](../../src/ui/RegionalChart.js) · [좌표와 배치](../../src/geospatial/regionalChart.js)

부산 앞바다를 나는 플레이어가 창밖의 다리를 보고 “저게 광안대교인가?”라는 질문을 떠올린다. 지도를 펼쳐 다리 양끝이 닿는 해안의 모양을 맞춰 보고, 지도에서 다리를 짚어 이름을 확인한다. 이처럼 눈에 보이는 지형을 지도와 대조해 위치를 알아내는 **지문항법**이 이 기능의 목표다. [이슈 #868의 조사와 결론](https://github.com/stlim0727/flight3d/issues/868)

## 첫 버전의 범위

부산 순항에서 시작하는 **C172 1인 자유비행**을 첫 검증 대상으로 제안한다. 조종석과 외부 시점 모두 한 장의 접이식 지형도를 쓴다. 지도를 처음 읽는 사람은 기체 표시의 도움을 받고, 익숙한 사람은 창밖과 해안선의 모양을 직접 맞춰 볼 수 있다. 다른 지역으로 넓힐 때도 이미 발견한 빌딩·지형지물의 이름과 위치를 활용한다. [부산 순항 시작점](../../src/config/regionalCruises.js) · [현재 랜드마크 데이터](../development/landmarks.md)

| 구분 | 결정 |
| --- | --- |
| 이슈에서 채택한 방향 | 현실성을 위해 지도를 읽는 동안에도 비행은 계속 진행한다. 창밖 풍경과 지도를 함께 보고, 지도를 열 때마다 내 기체를 중앙에 둔다. 빌딩·지형지물의 이름과 거리는 지도로 옮긴다. 지도를 펼칠 때 종이 소리가 난다. [추가 요구사항](https://github.com/stlim0727/flight3d/issues/868#issuecomment-7064058503) |
| 첫 버전 제안 | 북쪽 위·기체 표시 켬으로 처음 열기, 기수 위로 전환, 지형지물 선택, 확인 지점 한 곳까지의 거리, 지도를 접을 때 현재 기체 위치에서 원래 카메라 시점으로 복귀. |
| 후속 후보 | 기체를 숨기고 내 위치를 짚는 연습, 737 조종석의 전자 항법 화면 확대와 다음 경유지 확인. |

## 기능 요구사항

| ID | 플레이어 행동 | 기대 결과 |
| --- | --- | --- |
| F1 | 부산 자유비행에서 도시를 본다. | 건물·다리의 3D 형상과 비행 계기는 보인다. 기존 풍경 위에 뜨던 랜드마크 핀과 `이름 · 거리` 표시는 지도에서 확인한다. 조종석과 외부 시점에 모두 `지도 펼치기` 버튼이 있다. [현재 핀 표시](../../src/ui/LandmarkPins.js) |
| F2 | 비행 중 지도를 펼친다. | 펼치는 순간의 기체 위치가 지도 중앙에 온다. 지도를 읽는 동안에도 비행 시간이 흐르고 창밖 풍경이 기체 이동에 따라 변한다. 소리가 켜져 있으면 종이 펼치는 소리가 한 번 난다. 같은 열람 중 지점을 고르거나 지도를 돌릴 때는 효과음을 반복하지 않는다. |
| F3 | 창밖과 지도를 번갈아 본다. | 해안선·육지·바다·다리 양끝을 구분할 수 있다. 기체 아이콘의 코는 실제 기수가 향하는 쪽을 가리킨다. 외부 카메라를 기체 옆으로 돌려도 이 기준은 같다. 지도와 풍경에는 동일한 지형지물 위치를 사용한다. |
| F4 | 나침반의 `북쪽 위`를 눌러 `기수 위`로 바꾼다. | 북쪽 위에서는 기체 아이콘이 방위를 나타낸다. 기수 위에서는 아이콘의 코가 위를 향하고 해안선과 북쪽 표시가 함께 돌아간다. 두 방향 모두 축척을 표시한다. |
| F5 | 지도에서 관심 있는 건물이나 다리를 짚는다. | 선택한 대상의 이름을 읽을 수 있다. 기체 표시와 그 지점까지의 수평거리(km)는 현재 비행 상태에 맞춰 갱신된다. 이름과 거리 표시는 풍경을 가리지 않는다. 빈 바다를 눌렀을 때는 기존 확인 지점을 유지한다. |
| F6 | `다음 확인 지점으로 표시`를 누르고 비행한다. | 같은 비행에서 한 곳을 기억한다. 다른 대상을 살펴보기만 하면 기존 지점을 유지하고, 새 대상을 확인 지점으로 지정하면 교체한다. 다시 펼치면 지금 기체 위치를 중심으로 해당 지점까지의 거리를 새로 표시한다. |
| F7 | `지도 접기`를 누른다. | 현재 기체 위치와 자세에서 원래 카메라 시점으로 돌아간다. 지도에서 누르거나 끌던 입력은 비행 조작으로 이어지지 않는다. 메뉴와 브라우저 비활성에 따른 정지 규칙은 기존 비행과 같다. |

지도 데이터가 늦게 도착하면 풍경과 `지도 접기`를 계속 제공하고, 빈 영역에 `지도 불러오는 중`을 표시한다. 읽을 수 없는 영역에는 지형이나 거리를 추정해서 그리지 않는다. 종이 소리는 게임의 음소거 설정을 따른다.

## 부산 바탕지도의 좌표 설계

[2단계 이슈 #929](https://github.com/stlim0727/flight3d/issues/929)의 지도는 부산 순항 출발점(북위 35.142°, 동경 129.075°)에 동·남 방향의 미터 평면을 고정한다. 지도 중심은 펼칠 때의 기체 위치로 정하고, 열람 중에는 기체 표시가 그 평면 위를 이동한다. 다시 펼칠 때 중심을 갱신한다. 아래 변환은 [기존 타일 좌표 함수](../../src/geospatial/TileCoordinateSystem.js)를 사용한다.

| 입력 | 부산 지도 평면까지의 변환 |
| --- | --- |
| 기체 위치 | [부산 순항](../../src/config/regionalCruises.js)은 인천 원점 기준의 월드 `(x,z)`를 쓴다. `localToWgs84(x,z,활성 월드 원점)`으로 위경도를 복원하고 `wgs84ToLocal(위도,경도,부산 출발점)`으로 지도 좌표 `(E,S)`를 얻는다. 고도는 투영에 들어가지 않는다. |
| 해안선·교량 | MVT 꼭짓점 `(u,v)`와 그 피처의 `extent`에 대해 `tileToWgs84(tx + u/extent, ty + v/extent, zoom)`를 적용한 뒤 동일한 부산 평면에 투영한다. 타일 좌표의 원점은 북서 모서리이며 `v`는 남쪽으로 증가한다. |
| 기수 | 월드에서 기체의 전방 벡터를 수평면에 투영해 정규화한다. 기체 위치와 그 방향 10 m 앞 점을 각각 부산 평면으로 옮긴 뒤 `h = atan2(ΔE, −ΔS)`로 지도 북쪽 기준 방위각(라디안)을 구한다. 수평 성분이 사라지면 마지막 유효 방위를 유지한다. |

부산 출발점은 월드에서 `(238677.88, 252496.41) m`다. 그곳의 진북은 월드의 `−Z`에서 서쪽으로 약 1.51° 기울어 있다. 출발 기수 66°(월드 기준)를 같은 평면으로 옮기면 지도에서 약 67.58°다. 이 차이는 투영으로 처리한다. 부산 평면의 북쪽 기준은 고정 원점의 진북이다.

**화면 변환.** 지도 중심을 뺀 지점의 좌표를 `(e,s)`, 축척을 `m`(m/CSS px), 화면 중심을 `(cx,cy)`라 한다. 북쪽 위에서는 `a = 0`, 기수 위에서는 현재 기수 방위 `a = h`다. 화면은 오른쪽·아래 방향이 양수다.

```text
px = cx + ( e·cos(a) + s·sin(a)) / m
py = cy + (−e·sin(a) + s·cos(a)) / m
```

기체 아이콘은 위를 향한 원본에서 시계방향으로 `h − a`, 북쪽 화살표는 `−a`만큼 돌린다. 축척 막대 길이는 `표시 거리(m) / m` CSS px다. DPR은 캔버스 해상도에만 적용한다. 예를 들어 20 m/px에서 지도 중심의 정동쪽 1 km 지점은 북쪽 위에서 오른쪽 50 px, 동향 기수 위에서 위쪽 50 px에 온다. 두 화면 모두 1 km 막대는 50 px다.

**타일과 해안선.** 회전한 화면 네 모서리를 역변환해 위경도 범위를 구하고 `tilesForBbox`로 z13 타일을 선택한다. 타일 내부에서 꼭짓점이 `extent` 밖에 걸쳐 있을 수 있으므로 도형을 타일 사각형으로 클립하고 원래 선분만 교량 외곽으로 그린다. 타일을 자르며 생긴 경계선은 해안선이나 교량 끝으로 표시하지 않는다. 수면은 [3D 지형의 물 마스크](../../src/environment/OpenWorldTerrain.js)와 같은 `base.water` 폴리곤과 구멍, 간헐 수면·수영장 제외 조건을 쓴다. 미수신 타일은 자료 대기 영역으로 남긴다.

**광안대교 검증점.** 고정 릴리스 `2026-11-18.0/base.pmtiles`의 z13에서 `광안대교` 폴리곤(`22922f0c…`)은 바다 위 중앙 경간만 덮는다. 양쪽 접근 구간은 `base.infrastructure`의 `광안대로` 교량 선형까지 그려야 해안에 이른다. 아래는 각 접근 구간 선형과 물 폴리곤 경계가 만나는 교점이다. 좌표는 데이터 대조용이며 도형은 원본 타일에서 읽는다.

| 대조 지점 | z13 타일 x/y · 교량 피처 ID | 북위, 동경 | 부산 평면 (동, 남) m |
| --- | --- | --- | --- |
| 남서쪽 접속부 | 7034/3241 · `9a7a892b-dc2b-3400-bb10-36bb51c7ddf6` | 35.136391°, 129.114404° | (+3591.2, +621.6) |
| 북동쪽 접속부의 한 갈래 | 7034/3240 · `86c725f9-5f81-34d0-a312-4356dfe9caac` | 35.163739°, 129.131766° | (+5171.7, −2413.3) |

구현 검증은 이 두 타일부터 시작한다. 공통 경계의 같은 점(예를 들어 위 타일의 `u/extent=0.25, v/extent=1`과 아래 타일의 `0.25, 0`)의 화면 좌표가 0.01 CSS px 이내로 일치해야 한다. 두 방향 모두에서 각 접근 선형과 해안선의 교점이 표의 기준점을 투영한 위치에서 1 CSS px 이내에 오는지 확인한다. 동향 기체를 옆에서 보는 외부 카메라로 전환해도 기수 위 지도에서는 북쪽이 왼쪽, 기체 코가 위에 있어야 한다.

## 화면 초안

### 1. 비행 중 → C172 조종석에서 펼침

평소에는 앞유리 너머로 이름표 없는 다리가 보이고 비행 도구에 **지도 펼치기**가 있다. PC 조종석에서 누르면 화면 중앙에 큰 지도가 펼쳐지고 뒤의 풍경과 계기는 흐려진다. 지도 오른쪽 아래의 **지도 접기**를 누르면 현재 위치에서 원래 시선으로 비행을 이어간다. 터치 화면과 좁은 창에서는 아래의 무릎 지도 배치를 쓴다.

| 화면 영역 | 펼친 직후 | 다리를 짚은 뒤 |
| --- | --- | --- |
| 위 · 앞유리 | 비행 중인 기체에서 보이는 해안선과 다리 | 기체가 이동하면서 달라진 다리의 위치와 크기 |
| 아래 · 무릎 위 지도 | 중앙에 내 기체, 주변에 해안선·다리, 모서리에 축척과 `북쪽 위 ▾` | 지도 위 다리를 강조하고 가장자리에 `광안대교 · 2.4 km`와 `다음 확인 지점으로 표시` |
| 지도 끝 | `지도 접기` | 같은 위치에 `지도 접기` |

아래는 이슈에 첨부된 부산 접이식 지형도 시안이다. 표의 2.4 km는 화면 문구를 설명하기 위한 예시값이다.

### 2. 외부 시점에서 펼침

PC 외부 시점에서도 조종석과 같은 크기의 지도를 중앙에 펼치고 배경을 흐리게 한다. 지도를 접으면 선택한 외부 카메라에서 비행을 이어간다. 아래 분할 배치는 터치 중심 기기 또는 너비 600 CSS px 이하의 화면에 적용한다.

| 가로 화면 · 왼쪽 | 가로 화면 · 오른쪽 |
| --- | --- |
| 원래 외부 카메라 각도에서 보는 현재 기체와 다리 | 종이 지도 · 기체 · 나침반 · 축척 |
| 풍경을 보며 해안 굴곡을 비교 | 선택한 지점 정보 · 확인 지점 지정 · 지도 접기 |

세로 화면은 **위에 같은 풍경, 아래에 같은 지도**를 둔다. 지도를 펼쳤다는 이유로 외부 카메라를 기수 정면으로 돌리지 않는다. 좁은 화면에서는 선택 정보가 지도 가장자리에 붙고, 접기 버튼과 선택한 다리는 계속 보인다.

### 3. 737 조종석에서 펼침 · 후속

앞유리 일부와 주변 계기를 남긴 채 ND에 시선을 가까이 둔다. 화면에는 기체, 선택한 목적지, 방위와 남은 거리가 보인다. 종이 지도와 전자 화면의 조작을 구별하기 위해 종이 펼침음은 접이식 지도에 적용하는 것으로 제안한다.

## 인수 기준

1. **지형 대조** — 부산을 처음 보는 사용자가 다리가 보이는 장면에서 지도를 한 번 열고, 다리를 짚어 이름을 확인한 뒤 자신이 다리의 육지 쪽인지 바다 쪽인지 설명한다. 풍경 위에 빌딩·다리 이름표가 나타나면 실패다.
2. **방향** — 동쪽을 향한 기체를 옆에서 보는 외부 시점으로 연다. 북쪽 위에서 아이콘 코가 오른쪽, 기수 위에서 위쪽을 가리키며 지도 속 북쪽이 왼쪽으로 이동한다.
3. **비행의 연속성** — 활성 창에서 순항 중 지도를 펼치고 5초간 다리를 선택하거나 지도 방향을 바꾼다. 열람 중 시뮬레이션 시각이 흐르고 기체가 이동한다. 접는 순간에도 시간과 경로가 이어지며, 현재 위치에서 원래 카메라 시점으로 돌아온다.
4. **선택과 거리** — 다리를 지정하고 접은 뒤 다리에 접근해 다시 연다. 기체가 다시 중앙에 오고, 같은 다리의 남은 거리가 줄어든다. 다른 빌딩을 살펴봐도 명시적으로 바꾸기 전까지 지정한 다리를 기억한다.
5. **소리와 작은 화면** — 음소거 해제 상태에서 두 번 열고 접으면 펼침음이 두 번 들린다. 음소거 상태에서는 들리지 않는다. 휴대전화 세로 화면에서도 다리를 탭하고 지도를 접는 동작을 끝낼 수 있다.
